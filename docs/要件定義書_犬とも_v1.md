# 趣味特化型マッチングアプリ 要件定義書・基本仕様書

**バージョン**: v1.0（ドラフト）
**対象スコープ**: 第2弾「犬とも」v1 / v1.5（ビジネスユーザー）
**作成日**: 2026年2月
**ステータス**: 要件確定待ち（法務レビュー項目あり）
**参考**: 第1弾「飯とも」の要件定義書・実装（Meshitomo-app-prototype）を本アプリのドメインに適用した第二弾。

## 1. 概要

### 1.1 目的

犬を飼っている飼い主さん同士を、**顔ではなく趣味・中身ベース**でマッチングし、以下を実現する。

1. 一般ユーザー同士：今から・近くで、犬とも（お散歩・ドッグラン仲間）を探して一緒に遊ぶ
2. 一般ユーザー：近くの犬OK公園・ドッグランを探してGoogleマップで開く
3. ビジネスユーザー：AI接客・地図連携で、近隣の飼い主さんに店舗（ドッグラン・サロン・ドッグカフェ等）を知ってもらい来店へつなげる
4. コミュニティ：常連・同じ犬種の飼い主さん同士のグループ、犬種オフ会などのイベント企画

### 1.2 コンセプト上の設計原則

| 原則 | 内容 |
|---|---|
| 飼い主の顔画像禁止 | プロフィール画像は「犬に関連する画像のみ」許可（愛犬の写真、お散歩風景、ドッグランの写真など）。**愛犬の顔はむしろ推奨**。飼い主本人の顔が写った画像はアップロード不可（モデレーションで拒否・削除） |
| 恋愛目的禁止 | 利用規約で「恋愛・異性交際目的の利用」を明示的に禁止。違反は BAN 対象 |
| 時限性 | 募集は期限付き（1〜3時間）。期限が来たら自動消滅。「今から」感が出会い系化を防ぐ |
| 距離の粗表示 | 正確な位置は非公開。「〜1km / 1〜3km」のような大ざっぱな距離のみ表示 |
| ペットファースト | ワンちゃんの安全・体調を最優先する文言・機能設計（無理な勧誘をしない、ワンちゃん合わせは段階的に） |

### 1.3 前提と未確定事項（法務レビュー必須）

| 項目 | v1 の対応 | 備考 |
|---|---|---|
| 出会い系サイト規制法 | サービスの実質を「犬仲間探し」とし、規約・モデレーションで異性交際目的利用を排除 | 弁護士による非該当性確認を必須とする。飼い主の顔画像禁止・一言メッセージ制は非該当性の根拠になる設計 |
| 未成年利用 | **v1 は18歳以上のみとする**（第1弾と同じ） | ペット業態は酒類を扱わないため「18歳以下も使用可」は v2 以降で法務確認の上検討 |
| 獣医療法の広告制限 | 動物病院のビジネスユーザー登録時、獣医療法の広告規制（認可のない治療法・症例数の誇示等）を案内文案から排除する審査を指定 | 業態別の広告ガイドライン整備が必要 |
| ペット関連の安心安全 | ドッグラン・ワンちゃん同士の遊びは飼い主の責任で行う旨を規約に明記。アプリは媒介であり安全を保証しない | トラブル（咬傷等）を想定した免責規約の整備 |
| 迷惑防止条例（客引き） | ビジネスユーザーの営業・AI接客はアプリ内完結とし、押しつけのない設計（一斉配信はしない）。オプトアウト手段を常時提供 | 個別自治体への確認は開発中に実施 |
| 個人情報保護法 | 位置情報・嗜好データの第三者提供は「匿名加工統計」に限定 | 店舗ダッシュボードには集計値のみ表示 |
| 動物愛護法 | 譲渡・里親目的の利用は原則禁止（mismatch 防止）。保護犬・譲渡会情報はアプリ外リンクの紹介のみ | 譲渡会をイベントとして登録する場合は商用でないことを確認 |

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 一般ユーザー | 無料で利用する飼い主さん（個人）。犬ともを探す側 |
| ビジネスユーザー | 有料プランで登録する店舗・事業者・個人営業主（ドッグラン、ペットサロン、ドッグカフェ、動物病院、ペットホテル、しつけ教室、ペット用品店など） |
| 募集（Recruitment） | 飼い主さんが近隣に向けて時限で発信する「参加者募集」（お散歩 / ドッグラン / ドッグカフェ）。投稿から1/2/3時間後に自動消滅 |
| 応募（Application） | 募集への参加申請。主催者が承認するとグループチャットが生成される |
| コミュニティ | 常設のグループ（犬種別オフ会、ドッグラン常連会、保護犬カフェ等）。誰でも作成可、参加自由（承認制も選択可） |
| イベント | コミュニティまたは個人が企画する日程付きの集まり（ワンちゃん撮影会、ドッグラン遠征など） |
| 公園・ドッグラン検索 | 現在地近くの犬OK公園・ドッグランを一覧表示し、Googleマップ（標準URL）で開ける機能。ワンタップで「その公園で募集」も可能 |

## 4. ペルソナ

### 一般ユーザー
- 20代〜50代、一人暮らし・引っ越しが多い、あるいは愛犬の犬友達がいない
- 「休日にドッグランへ連れて行きたいが、犬友達がいない」「同じ犬種・同じサイズのワンちゃんと遊ばせたい」
- 恋愛マッチングアプリには抵抗がある（恋愛目的でない人）
- 引っ越してきて犬友達を作りたい

### ビジネスユーザー
- ドッグラン・ペットサロン・ドッグカフェ・動物病院・ペットホテル等の経営者
- 「雨天・閑散時間に来店を増やしたい。新規の飼い主さんとの接点が少ない」「AI接客で問い合わせ対応と、地図から来店への導線を強化したい」
- 月額数千円〜1万円程度の予算感で、新規顧客よりも「リピーター・常連コミュニティ」を増やしたい

## 5. 機能要件

### 5.1 会員登録・認証

| 要件 | 内容 |
|---|---|
| FR-1-1 | SNS 認証（Apple / Google / LINE）。v1 では電話番号認証を必須としないが、通報対策としてアカウント単位のレート制限を実装 |
| FR-1-2 | 登録時の必須入力：ニックネーム、年代（10歳刻み表示、生年非公開）、性別（非公開も選択可）、居住エリア（市区町村レベル）、興味カテゴリ（複数選択：お散歩/ドッグラン/ドッグカフェ/しつけ/アジリティ/愛犬撮影/おやつ研究/旅行/健康/トリミング/保護犬/多頭飼い 等 12種＋ユーザー自由追加）、愛犬と飼い主さんの紹介の自由記述（140字、「犬ともステータス」） |
| FR-1-3 | **アイコンは写真アップロードまたは提供アイコンセットからの選択**。アップロード画像は **飼い主の顔** を AI 顔検出で自動審査し、顔が検出された場合は拒否。**愛犬の顔・体は投稿可（推奨）** |
| FR-1-4 | 年齢確認：生年月日を入力させる（18歳以上チェック用）が、プロフィールには公開しない |
| FR-1-5 | 退会：アカウント削除時のデータ保持期間（アクティブデータ即時削除、バックアップ90日）を規約に明記 |

### 5.2 近くの飼い主さん・募集（コア機能）

| 要件 | 内容 |
|---|---|
| FR-2-1 | 「募集をかける」：以下を指定して募集を発信できる |
| | - ジャンル（お散歩 / ドッグラン / ドッグカフェ） |
| | - タイトル・本文（例：「今から夕方の公園でお散歩しませんか。柴犬（4歳・男の子）同伴、小型犬も歓迎」） |
| | - 条件設定：性別指定（任意）、人数上限、犬種・サイズの言及（自由記述） |
| | - 有効期限（1 / 2 / 3 時間、期限切れで自動消滅） |
| | - 待ち合わせ場所：公園名・ドッグラン名（「近くの公園」タブからワンタップで設定可） |
| FR-2-2 | 「近くの人」リスト：現在地から粗い距離（〜1km / 1〜3km / 3〜5km / 5〜10km）で、近くのアクティブな募集・ユーザーを一覧表示。並び替え：距離×新着 |
| FR-2-3 | 検索：ジャンル、キーワード、距離、興味カテゴリでフィルタ可能 |
| FR-2-4 | **近くの公園・ドッグラン検索（本アプリの特別機能）**: 現在地近くの犬OK公園・ドッグランを一覧表示（種別、特徴タグ、距離バンド、説明）。各公園は「Googleマップで開く」（標準URLスキーム。APIキー不要）でGoogleマップに遷移する。「この公園で募集」ボタンで待ち合わせ場所を初期設定した募集を作成できる。プロトタイプは端末内シード。本開発では Google Places API（dog_park / park）または OpenStreetMap（Overpass API）で取得 |
| FR-2-5 | 募集は同一ユーザーが同時に1件まで（スパム防止） |

### 5.3 応募・交流

| 要件 | 内容 |
|---|---|
| FR-3-1 | 応募：募集詳細から「参加したい」ボタンで応募。一声メッセージ（任意、140字） |
| FR-3-2 | 主催者は応募一覧から承認／却下。承認人数が上限に達したら募集は自動的に締切 |
| FR-3-3 | 承認されたメンバーでグループチャットが自動生成。参加者はその後も辞退可能 |
| FR-3-4 | 1:1 のダイレクトメッセージは募集への応募経由でのみ送れる設計（いきなり DM される対策） |
| FR-3-5 | 万一に備えた安全機能：ブロック／通報は一般ユーザー間と同一水準。ワンちゃん同士の相性トラブルを考慮し「この募集は初対面同士でも安心な内容か」を投稿時に案内 |

### 5.4 プロフィール・中身重視設計

| 要件 | 内容 |
|---|---|
| FR-4-1 | 趣味・嗜好の表現をリッチにする（お散歩の時間帯、ドッグランの好きな理由、しつけの考え方、愛犬の犬種・年齢・性格）を「犬ともステータス」としてマイページに表示 |
| FR-4-2 | 過去の参加募集数、参加者からの評価（「また一緒に遊んだ」ボタン式、v1.5 実装）を表示 |
| FR-4-3 | ブロック／通報：非表示、通報（理由入力）。通報数が閾値超過で自動凍結 → 人力審査 |

### 5.5 ビジネスユーザー（v1.5）

| 要件 | 内容 |
|---|---|
| FR-5-1 | 店舗登録：店舗名、業態（審査対象：ドッグラン、ドッグカフェ、ペットサロン・トリミング、動物病院、ペットホテル、しつけ教室、ペット用品店、保護犬・譲渡会運営、その他）、住所、営業時間、写真（店舗・ドッグラン・ワンちゃん OK。**飼い主本人の顔写真禁止は一般ユーザーと同じ基準**） |
| FR-5-2 | **AI接客（有料機能）**: ビジネスユーザーは店舗情報を登録するだけで、AI（LLM）が来店前の質問対応・案内（犬種 OKか、料金、初めてのワンちゃんへの対応、営業時間等）を行う |
| FR-5-3 | **地図連携**: 近くの店舗をアプリ内マップ（OpenStreetMap タイル、APIキー不要）にピン表示。各店舗は「Googleマップで開く」（標準URL）。本開発で Google Maps SDK に移行し経路案内まで表示 |
| FR-5-4 | 効果測定: AI接客の応答数・来店導線・閑散時間のアクセス推移を店舗ダッシュボードに表示 |
| FR-5-5 | 課金：月額制（ライト／スタンダード／プレミアム）。決済は Stripe / RevenueCat 等の標準的な手段を利用 |

### 5.6 コミュニティ・イベント

| 要件 | 内容 |
|---|---|
| FR-6-1 | コミュニティ作成：誰でも可（名前、説明、カテゴリ、公開／承認制、地域）。犬種別オフ会、ドッグラン常連会、保護犬カフェ等 |
| FR-6-2 | イベント：コミュニティに紐付けて日程・公園／ドッグラン名・募集ワンちゃん数を設定し、参加受付 |
| FR-6-3 | ビジネスユーザーも一般ユーザーも同じコミュニティに参加可 |

## 6. 非機能要件

| 項目 | 要件 |
|---|---|
| プラットフォーム | iOS / Android（Flutter）。Web 管理画面（モデレーション用） |
| 位置情報プライバシー | 位置情報は端末側で geohash（精度レベル5〜6程度）に変換して送信。サーバーには生の緯度経度を保持しない。退会時に即時削除 |
| セキュリティ | TLS 通信、認証トークン（短期＋リフレッシュ）、パスワードレス（SNS認証） |
| 応答性能 | 募集の一覧取得は P95 200ms 以内（キャッシュ活用）。プッシュ通知は P95 30秒以内 |
| 拡張性 | 趣味カテゴリ（第1弾:飯とも、第2弾:犬とも、次弾:車/バイク/釣り/キャンプ等）はマスタデータ化し、アプリ再リリースなしで追加可能 |
| モデレーション | AI 審査（**飼い主の**顔画像検出、禁止ワード）＋人力審査ワークフロー。通報 → 凍結 → 審査の SLA 48時間 |
| アナリティクス | 登録 → 募集投稿 → 応募 → 成立（チャット生成） → 実参加（チェックイン）→ リピートのファネル KPI を計測 |

## 7. データモデル（概要）

```
users (id, auth_provider, nickname, birth_decade(非公開), gender, gender_public,
       city_geohash, role [general|business], status, created_at)
profiles (user_id, bio, dog_info_json, interest_ids_json,
          participation_count, rating_score, icon_media_id)
media (id, owner_user_id, media_type [icon|store_photo], moderation_status)
recruitments (id, host_user_id, genre_id [sanpo|dogrun|dogcafe], title, body,
              capacity, expires_at, meetup_name,
              status [active|fulfilled|expired|cancelled], created_at)
applications (id, recruitment_id, applicant_user_id, message,
              status [pending|accepted|declined], created_at)
rooms (id, recruitment_id, type [group], created_at)
room_members (room_id, user_id, joined_at, left_at)
messages (id, room_id, sender_user_id, body, created_at)
communities (id, name, description, category_id, visibility, owner_user_id, created_at)
community_members (community_id, user_id, role, joined_at)
events (id, community_id, title, starts_at, location_name, capacity, status)
parks (id, name, place_type [park|dogrun], google_place_id, location_geohash,
       features_json, last_checked_at)        -- 本開発: Google Places / OSM から取得
stores (id, business_user_id, name, industry_type, address, geohash,
        business_hours_json, created_at)
ai_concierge_logs (id, store_id, user_id, question, answer, created_at)
reports (id, reporter_user_id, target_type, target_id, reason, status, reviewed_at)
blocks (blocker_user_id, blocked_user_id, created_at)
subscription_plans (id, name, price, features_json)
subscriptions (id, store_id, plan_id, status, period_start, period_end)
```

設計メモ：
- 募集の期限切れは毎分のバッチで `status` を `expired` に更新。クライアントは `_expires_at` を見て表示制御も行う（二重防護）
- 公園は外部データ（Google Places / OSM）を `parks` に同期し、`google_place_id` で「Googleマップで開く」URL を組み立てる
- 距離検索は geohash プレフィックス照合で実装し、生の緯度経度での距離計算はクライアント側で行わない

## 8. 画面フロー

```
[初回起動]
  オンボーディング（コンセプト説明 + 恋愛目的禁止の同意）
    → 認証（プロトタイプ: メール）
    → プロフィール入力（ニックネーム / 年代 / 興味カテゴリ / 愛犬紹介 / アイコン）
    → 位置情報・通知の権限リクエスト
    → ホーム

[一般ユーザー ホーム（タブ構成。本体は下部5タブ、内「近く」に4セグメント）]
  1. 近く（デフォルト）
     - 切替: [募集] [人] [店] [公園]
     - 募集: アクティブな募集カード（距離・残り時間・人数・ジャンルタグ・主催者の嗜好）
     - 公園: 近くの公園・ドッグラン一覧（「Googleマップで開く」「この公園で募集」）
     - 「募集をかける」フローティングボタン
  2. 部屋（チャット一覧）
  3. コミュニティ（＋イベント・クラブ企画）
  4. 探す（興味カテゴリで近くの人を探す）
  5. マイページ（プロフィール編集、設定、招待）

[募集フロー]
  募集作成 → 投稿 → 近くの人に表示
  閲覧者が「参加したい」→ 主催者に通知 → 承認 → グループチャット生成
  期限到来 → 自動消滅

[ビジネスユーザー ホーム]（v1.5）
  ダッシュボード（AI接客応答数 / 来店傾向） / 店舗ページ編集 / AI接客の設定 / 地図連携設定 / プラン管理
```

## 9. KPI

| フェーズ | KPI |
|---|---|
| 起動初期（0〜3ヶ月） | 週次アクティブユーザー（WAU）、募集投稿数/日、募集あたり応募数、「公園」タブ→募集作成の転換率 |
| 定着（3〜6ヶ月） | 募集成立率（投稿→チャット生成）、成立後チェックイン率、リピート犬とも率（同一ユーザーと2回以上） |
| 収益化（6ヶ月〜） | ビジネスユーザー数（ドッグラン・サロン・病院）、AI接客経由来店数、解約率、LTV |

初期は犬種の近さよりも「募集あたり応募数」が最重要。1.0を下回る場合、リリース地域を都市部の公園密集地に絞る。

## 10. カテゴリ拡張戦略

第1弾「飯とも」、第2弾「犬とも」で共通のプラットフォーム（認証・募集・コミュニティ・地図連携・ビジネス課金）が確立できた前提で、次に拡張するカテゴリは以下の基準で選ぶ：

1. 一般ユーザーの行動頻度が高い（週1回以上）
2. ビジネスユーザーが明確に存在し、課金対象（AI接客・地図連携）になる
3. 周囲への「募集」が自然に多発する（ナインモンスターズ的方式の近隣勧誘が機能する）

この基準でいえば、「犬とも」はビジネスユーザー（ドッグラン、ドッグカフェ、トリミングサロン、動物病院）が明確で収益性が高い。かつ「近くの公園」という特別機能で屋外行動を促進できる。次弾は「車/バイク」（ガソリンスタンド、カー用品店）→「キャンプ」（アウトドアショップ）を検討。
